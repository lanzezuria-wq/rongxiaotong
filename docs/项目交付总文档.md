```

├── README.md                      ← 启动入口：怎么跑、账号、测试命令
├── demo1/                         ← 后端（Spring Boot 4.1.1 + Java 17），单 Maven 模块

└── test.txt                       ← P2 提交的空文件（历史遗留，未使用）
```

> **为什么后端是单模块而不是多模块？** 4 人并行、两周工期，多模块 Maven 的聚合/继承配置
> 和 IDE 重导入成本远大于收益。改成「**单模块 + 模块子包隔离**」：物理上一个 jar，
> 逻辑上按包把人分开，谁也不用动谁的目录。

### 2.3 子包的职责（每个模块包内结构一致）

| 子包 | 放什么 | 规则 |
|---|---|---|
| `constant` | 状态枚举、业务常量、状态名翻译 | 状态取值集中一处，别处不许硬编码数字 |
| `config` | 该模块专属的配置类 | P3 只有一个 `MockConfig` |
| `entity` | 数据库表映射 | 与表一一对应，**不直接返回给前端** |
| `mapper` | MyBatis-Plus 的 `BaseMapper` 继承 | 无 XML；复杂查询才加方法 |
| `dto` | 入参 | 只放前端能决定的字段；**状态类字段刻意不放** |
| `vo` | 出参 | 静态工厂 `from(实体)` 显式赋值，不用反射拷贝 |
| `service` + `service/impl` | 业务逻辑 | 接口 + 实现分离，与 P1/P2 一致 |
| `controller` | HTTP 入口 | 只做参数绑定 + 权限注解，业务逻辑一行不写 |

> **⚠️ 新增模块时必须在 `RxtApplication` 的 `@MapperScan` 里加一行**（不是通配符）。
> 漏了会在启动时报 `Consider defining a bean of type 'xxxMapper'`。

| 12 | `README.md` | 改成项目级入口（原来只写 P1） | 无 |

**关于第 5 项（`SecurityConfig`）**：新增规则全部**插在 `anyRequest().authenticated()` 之前**，
并且每条都带 `HttpMethod` 限定。漏掉 HTTP 方法限定会让"只读接口放行"变成"整个路径放行"——
这是 Spring Security 这类配置最典型的越权漏洞。

**关于第 11 项（`ApiIntegrationTest.m7UserList`）**：这条测试原本断言"用户总数 = 7"。
P2 加了一个演示买家账号（变 8）却没同步这条断言，**所以 P2 提交后测试就已经是红的**。
P3 又必须加 6 个种子账号（联保小组最少 3 人，只有 1 个农户根本演示不了核心功能），
于是改成**不依赖种子数量的不变量断言**：

- 总数用**下界**（`>= 7`）而不是等号
- 分页自洽（`pages == ceil(total / size)`）
- 筛 `role=expert` 时**返回的每一条都必须是 expert**（这才是筛选功能真正的不变量）
- 锚点账号存在（待审核专家「张农艺师」必须在待审列表里）

这样以后**任何人加种子账号都不会再弄红它**。

### 4.3 三种"冗余/派生数据"的维护策略（**最容易被写错的地方**）

这个项目里有意保留了若干冗余列（为了列表页不用连表聚合）。它们**各自只有唯一一个刷新入口**，
并且在同一个事务里更新，否则会出现"明细改了、汇总没改"的永久偏差。

| 类型 | 例子 | 策略 | 为什么 |
|---|---|---|---|
| **聚合类** | `t_guarantee_group.total_amount` / `current_members` | 成员变动后**重新 `SUM` / `COUNT`**（幂等） | 用 `±1` 只要漏掉一次加减就永久偏差；重算永远正确 |
| **计数类** | `t_article.like_count` / `t_article.comment_count` | `setSql("x = x + 1")` | 交给数据库原子自增，避免并发下"读-改-写"丢数；减法套 `GREATEST(0, x - 1)` 防负数 |
| **热度类** | `t_article.view_count` | 详情接口里 +1 | 允许轻微不准，不值得为它加锁 |

> 联保小组的"聚合类"刷新入口是 **`FinancingServiceImpl#syncGroupState` 这唯一一个方法**。
> 任何成员变动（加入 / 退出 / 取消申请）之后都必须调用它，**别处不许直接改**
> `current_members` / `total_amount` / `status` 这三个字段。

### 4.4 逻辑删除 vs 物理删除

| 表 | 删除方式 | 原因 |
|---|---|---|
| `t_user`、`t_article`、商品/订单等 | **逻辑删除**（`deleted=1`） | 有历史关联（订单要能查到下单用户），不能真删 |
| `t_guarantee_member` | **物理删除** | 成员退出小组后，这一行没有保留价值；且唯一索引 `uk_gm_group_user` 会因逻辑删除残留而阻挡"退出后再加入" |

### 4.5 一个必须记住的 DDL 坑：MySQL 关键字列名

`t_financing_apply` 有一个叫 **`usage`** 的列（资金用途）。`usage` 是 MySQL 的保留字：

- **DDL 里**建列时写了反引号 → 正常
- **但 MyBatis-Plus 生成的 INSERT 不带反引号** → 运行期直接 SQL 语法错误

所以实体类里必须写成 `@TableField("`usage`")`。以后再加关键字列名（`key`、`order`、`desc`…）
要同样处理。**这个坑在编译期完全看不出来，只有真正跑起来插数据才会炸。**

### 6.3 推送时的凭据（**已实测，结论和直觉不一样**）

**本机已经能直接推送。** 因为 Git 的凭据助手（`git-credential-manager`）里已经存了一份
有效凭据，所以下面这一句就能推上去，不用输密码：

```bash
git push origin master
```

**⚠️ 但华为云「账号密码」是不能用于 git 推送的。** 实测用账号密码会立刻被拒：

```
remote: <CH.00905401> HTTP Basic: Access denied. Request-id is 4RxsAqFQPC.
fatal: Authentication failed for '...springbo.git/'
```

原因是 CodeHub 用的是**仓库级的 HTTPS 密码（访问令牌）**，和华为云登录密码是两回事。
获取方式：**CodeHub 仓库页 →「设置」→「HTTPS 密码」→ 生成**，得到一串令牌。

| 场景 | 怎么做 |
|---|---|
| 正常提交（本机） | 什么都不用管，`git push origin master` 直接用系统已存的凭据 |
| 换机器 / 凭据失效 | 提示输入时：**Username** 填 `pgx1181`，**Password** 填**上面生成的 HTTPS 密码**（不是登录密码） |
| 想重新输入凭据 | 「控制面板 → 凭据管理器 → Windows 凭据」，删掉 `codehub.devcloud.cn-north-4.huaweicloud.com` 那一条，再 push 会重新提示 |

> ⚠️ **不要把密码写进 `.git/config` 的 remote URL 里**（`https://user:pass@...`）。
> 那会把明文留在仓库配置里，目录一旦被复制/上传就跟着泄露。
> 想确认配置是干净的，跑 `git remote -v`，输出里**不应该**出现 `用户名:密码@`。

### 6.4 常见情况处理

| 情况 | 处理 |
|---|---|
| 推送被拒绝（`! [rejected] ... non-fast-forward`） | 队友先推了。执行 `git pull --rebase origin master` 后再 `git push origin master` |
| `git pull --rebase` 报冲突 | 冲突文件里会标 `<<<<<<<`。**因为本次改动 90% 是新增文件，冲突通常只出现在 `README.md`、`SecurityConfig.java`、`ResultCode.java`、`RxtApplication.java` 这几个共享文件上**。逐个人工合并后 `git add <文件>` 再 `git rebase --continue` |
| 想撤销刚才的提交（还没推送） | `git reset --soft HEAD~1`（保留改动，只撤销 commit） |
| 想撤销刚才的推送 | `git revert <commit>` 生成一个反向提交再推（**不要用 `git push -f`**，会抹掉队友的提交） |
| 提交后发现漏了文件 | `git add <文件> && git commit --amend --no-edit`（仅限尚未推送时） |
| 只想提某几个文件 | `git add demo1/src/main/java/com/rxt/finance demo1/src/main/java/com/rxt/assist demo1/src/main/resources/sql/init_p3.sql docs tools` |

## 七、如何把项目跑起来

### 7.1 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | Boot 4.x 最低要求 17 |
| Maven | 3.9+ | 或直接用 IDE 内置的 |
| MySQL | **8.0+** | 5.7 不支持 `utf8mb4_unicode_ci` 的部分写法 |
| Node.js | 18+ | 前端用（P4） |

### 7.2 三步启动

```bash
# ① 建库（顺序不能反，三个脚本都是幂等的，可反复执行）
cd springbo
mysql -uroot -p < demo1/src/main/resources/sql/init.sql
mysql -uroot -p < demo1/src/main/resources/sql/init_trade.sql
mysql -uroot -p < demo1/src/main/resources/sql/init_p3.sql

# ② 起后端（默认 8080）
cd demo1
mvn spring-boot:run
# 验证：curl http://127.0.0.1:8080/api/ping

# ③ 起前端（默认 5173，已配 /api 代理到 8080）
cd ../rxt-frontend
npm install
npm run dev
```

接口文档（Swagger UI）：<http://127.0.0.1:8080/swagger-ui.html>

### 7.3 跑测试

```bash
cd demo1
mvn test
```

**两个本机已知的坑**（写在 README 里，这里再提一次）：

1. **surefire 跨盘会崩** → 必须加 `-DforkCount=0`
2. 加了 `-DforkCount=0` 之后 `-DargLine=` 会失效 → 数据源参数要作为 **Maven 系统属性**传：

```bash
mvn test -DforkCount=0 \
  "-Dspring.datasource.url=jdbc:mysql://127.0.0.1:3306/rxt_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true" \
  "-Dspring.datasource.username=root" "-Dspring.datasource.password=你的密码"
```

端到端脚本（需要后端已启动）：

```bash
python tools/p3-e2e-test.py
```

> ⚠️ 脚本会**写数据**。它期望"刚执行完三个 SQL 脚本"的初始状态，
> 重复跑会有几条断言失败（比如"已有进行中申请时重复提交"会因为上一轮的数据而误报）。
> 跑之前请重跑那三个 SQL 脚本。

### 7.4 常见启动问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Consider defining a bean of type 'xxxMapper'` | 新模块的 Mapper 包没加进 `@MapperScan` | 在 `RxtApplication` 的 `@MapperScan` 里加一行 |
| 列表接口返回了全部数据但 `total` 是对的 | MyBatis-Plus 分页插件没注册（**且不报错**） | 检查 `config/MybatisPlusConfig` 是否注册了 `PaginationInnerInterceptor` |
| 插数据时报 SQL 语法错误 | 列名是 MySQL 关键字（如 `usage`） | 实体字段加 `@TableField("`usage`")` |
| 前端请求 404 | Vite 代理把 `/api` 前缀 rewrite 掉了 | **不要加 `rewrite`** —— 后端路径本身就带 `/api` |
| 401 但密码是对的 | 请求没带 `Authorization: Bearer <token>` | 检查是否走了 `api/request.js` 的 axios 实例 |
