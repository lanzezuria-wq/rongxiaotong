### 3. 时间格式**不是 ISO** —— 这是最容易踩的坑

你的计划里写"后端返回 ISO `2026-09-18T14:30:00`，前端 dayjs 处理显示"。**实际不是。**

后端（`DateUtils`，全项目统一）返回的是：

```
"2026-09-18 14:30:00"        ← 空格分隔，无 T，无时区后缀，且已是北京时间
```

所以：

- ✅ 直接显示即可，**不要再 `dayjs(x).format()`**（再去解析一次等于把已格式化的串又解析一遍，多此一举还容易出错）
- ✅ `el-date-picker` 必须加 `value-format="YYYY-MM-DD HH:mm:ss"`，否则它默认输出 ISO 串，提交给后端会解析失败
- ⚠️ 反过来，**前端传给后端的**预约时间也必须是 `yyyy-MM-dd HH:mm:ss`（后端 `DateUtils.parse` 兼容带 `T` 的形式，但别依赖它）

### 4. 分页字段是 **`records`**，不是 `list`

```jsonc
// GET /api/financing/list 的返回
{ "code": 0, "message": "ok",
  "data": { "records": [ /* 数据在这 */ ], "total": 12, "page": 1, "size": 10, "pages": 2 } }
```

前端表格绑 `data.records`。**契约文档里写的是 `list`，不要照抄契约。**

### 5. 根路由现在是重定向到登录页，你要改

`src/router/index.js` 现在是 `{ path: '/', redirect: '/login' }`。
加了首页之后要改成 `{ path: '', component: HomeView }`，否则访问根路径永远进登录页。

## 三、你要做的 11 个页面（逐页对照）

### 融资（M4）

#### 1. `/financing/apply` —— 融资申请表单

| 项 | 内容 |
|---|---|
| 接口 | `POST /api/financing/apply` |
| 权限 | 仅 `farmer`（其他角色返回 **3004**） |
| 入参 | `amount` 金额 / `usage` 资金用途 / `industry` 行业 / `province` / `city` / `loanTerm` 期限 / `description` 用途说明 |
| 返回 | `{ "id": 12, "matchedGroups": [ ... ] }` |

**⚡ 这个接口有个体验设计要你配合**：提交成功后返回的 `matchedGroups` 是**后端顺手帮你匹配好的"可加入小组"**
（同行业 + 同省 + 招募中 + 未满员）。请直接弹一个对话框：

> 「为您匹配到 2 个联保小组，是否立即加入？」
> [看看小组] [稍后]

不这么做的话，农户提交完会卡在"我接下来该干什么"。匹配不到时 `matchedGroups` 是**空数组**（不是 null），
此时提示「暂无匹配小组，可先去[发起小组]」。

#### 2. `/financing/groups` —— 联保小组列表（可加入的）

| 项 | 内容 |
|---|---|
| 接口 | `GET /api/financing/groups?industry=&province=` |
| 返回 | `List<GuaranteeGroupVO>`（**不是分页**，直接是数组） |

**卡片上要显示的关键字段**：

- `currentMembers` / `maxMembers`（如 `3/10`）—— 用 `el-progress` 画进度条
- `remainingToForm` —— **后端已算好"还差几人成团"**，直接显示「还差 1 人成团」，**不要自己减**
- `statusName` —— 状态中文名，后端已翻译，直接显示
- `totalAmount` —— 组内申请金额合计

#### 3. `/financing/group/:id` —— 联保小组详情

| 项 | 内容 |
|---|---|
| 接口 | `GET /api/financing/group/{id}` → 含 `members[]` |
| 加入 | `POST /api/financing/join`，body `{ "groupId": 3, "applyId": 7 }` |

**⚠️ 两个必须注意的点**：

1. **加入要同时传 `groupId` 和 `applyId`**。`applyId` 是"用哪一条融资申请加入小组"。
   所以前置条件是：**用户得先有一条"待匹配"的融资申请**。如果没有，
   请引导他去 `/financing/apply`，否则后端会返回错误（申请状态不对）。
2. **没有"退出小组"接口**。退出 = **取消融资申请**（`DELETE /api/financing/apply/{id}`），
   后端会自动把人从小组里摘掉，并重算小组人数与金额。请不要在页面上画一个"退出小组"按钮去调不存在的接口。

#### 4. `/financing/my` —— 我的融资

| 项 | 内容 |
|---|---|
| 列表 | `GET /api/financing/list?page=&size=&status=` → `PageResult`（用 `records`） |
| 详情 | `GET /api/financing/{id}` → 比列表多 `description` / `group` / `approval` 三个字段 |
| 取消 | `DELETE /api/financing/apply/{id}` |

**详情页的字段结构要注意**：

```jsonc
{ "id": 7, "amount": 120000, "usage": "SEED",
  "status": 3, "statusName": "已通过",     // ← 申请自己的状态
  "group": { "id": 3, "status": 3, "statusName": "已通过", ... },   // ← 小组的状态（同名字段！）
  "approval": { "result": "APPROVED", "creditScore": 86,
                "interestRate": 4.35, "decisionAmount": 336000 } }
```

`status` 出现了两次（申请的、小组的）—— **别用"取第一个"的方式解析 JSON**，按对象层级取。

**审批结果卡片**（`approval` 非 null 时显示）：审批结论、信用评分、年化利率、核定额度、审批意见、审批时间。
拒绝时 `decisionAmount` 是 `null`（不是 0），请显示成「—」而不是「0 元」。

**申请状态机**（决定按钮的显示/禁用）：

```
0 待匹配 ──→ 1 已匹配 ──→ 2 待银行审批 ──→ 3 已通过
   │            │              │
   └────────────┴──────────────┴──→ 5 已取消（0/1/2 都可取消，3/4 不可）
                                └──→ 4 已拒绝
```

「取消」按钮只在 `status ∈ {0,1,2}` 时可用。**已被银行审批后取消会返回 3003。**

#### 5. `/bank/groups` —— 银行端联保小组列表

| 项 | 内容 |
|---|---|
| 接口 | `GET /api/bank/group/list?status=` |
| 返回 | `List<BankGroupVO>`，**总是带 `members[]`**（供逐项核验身份与金额） |

`status` 建议做 tab 切换：不传=全部 / `1`=已匹配 / `2`=待审批 / `3`=已通过 / `4`=已拒绝。
每行显示：小组编号 `groupNo`、行业、地区、成员数、申请总额 `totalAmount`，操作列「审批」。

#### 6. `/bank/approve/:id` —— 审批表单

| 项 | 内容 |
|---|---|
| 接口 | `PUT /api/bank/approve` |
| 入参 | `groupId` / `result`(`APPROVED`\|`REJECTED`) / `creditScore`? / `interestRate`? / `decisionAmount`? / `remark`? |

**⚡ 这个接口的核心是 Mock 模式**（配置项 `rxt.mock.enabled`，默认为 `true`）：

- **只传 `groupId` + `result` 就能完成审批**，信用分/利率/核定额度由后端自动生成：
  - 信用评分 60~100
  - 年化利率 3.85% ~ 7.00%
  - 核定额度 = 小组申报总额 × 80%~100%
- 表单上三个数值输入框**留空即可**（可以预填一个大概值让演示更直观，但留空也能过）
- 校验规则：`creditScore` 0~100、`interestRate` 3.85~7.00、`decisionAmount` ≥ 0，
  超出范围后端返回 **1001**（参数校验失败）
- **拒绝时 `remark` 必填**（跨字段规则，后端校验，前端最好也拦一下）

**⚠️ 审批结果不可撤回**：已审批的小组再提交会返回 **3006**。所以按钮点完要刷新状态、禁用掉。

**一次审批会影响三处状态**（后端在同一事务里做）：小组状态 + 组内**所有**申请的 `status` + `bank_id`。
所以审批完 `/financing/my` 里组内每个农户都能看到结果。

#### 7. `/bank/stats` —— 融资统计

| 项 | 内容 |
|---|---|
| 接口 | `GET /api/bank/stats` |
| 返回 | `{ totalGroups, pendingGroups, approvedGroups, rejectedGroups, totalApprovedAmount }` |

纯数字展示即可（你的任务清单里也标了"可砍图表"）。`totalApprovedAmount` 无数据时是 `0` 不是 null。

**状态字典（小组）**：`0` 招募中 / `1` 已匹配 / `2` 待银行审批 / `3` 已通过 / `4` 已拒绝
（`2` 是预留位，本模块不会写入，但字典要留这一项）

### 专家助力（M5）

#### 8. `/articles` —— 文章列表 + 详情 + 互动

| 操作 | 接口 | 权限 |
|---|---|---|
| 列表 | `GET /api/article/list?page=&size=&status=&keyword=` | 公开（游客可看） |
| 详情 | `GET /api/article/{id}` | 公开 |
| 发布 | `POST /api/article` | farmer / expert |
| 点赞 | `PUT /api/article/{id}/like` | 需登录 |
| 评论 | `POST /api/article/{id}/comment` | 需登录 |

**⚠️ 三个坑**：

1. **文章状态由角色决定，不由前端传**：
   - `farmer` 发布 → 后端存 `status=0`（待审核），**前端不要传 status**（DTO 里刻意没有这个字段）
   - `expert` 发布 → 后端存 `status=1`（直接发布）
   所以农户发布后请提示「已提交，等待管理员审核」，而不是「发布成功」。
2. **详情接口对游客也开放**，但未发布的文章只有作者本人和管理员能看，其他人访问返回 **4002**。
   游客访问时后端不返回 `isLiked`（因为不知道你是谁），前端要做判空。
3. **点赞是可切换的**，后端返回 `{ isLiked, likeCount }` ——
   **用返回值直接覆盖前端本地值，不要自己 ±1**（本地推算在重试/多端操作时会错位）。
   `isLiked`：`1` 已点赞 / `0` 未点赞。

#### 9. `/experts` —— 专家列表 + 详情

| 操作 | 接口 |
|---|---|
| 列表 | `GET /api/expert/list?page=&size=&specialty=` |
| 详情 | `GET /api/expert/{id}` （比列表多 `intro` + `recentArticles[]`） |

**⚠️ 这里有两个"专家 id"，是最容易接错的一处**：

| 接口 | 用哪个 id |
|---|---|
| `GET /api/expert/{id}`（本页）、`POST /api/question`、`POST /api/appointment` | **`t_expert.id`** = 列表返回的 `id` |
| `PUT /api/admin/expert/{id}/audit`（管理员的专家审核页，P1 的） | **`t_user.id`** = `userId` |

**列表返回的 `id` 直接往后传就对了**，不要传 `userId`。

> 后端只返回**已通过资质审核**的专家（`t_expert` 有记录 且 账号状态正常），
> 待审核的专家不会出现在这里 —— 所以你的列表页不会出现"点进去发现不能咨询"的情况。

字段映射（契约名 vs 实际来源，做表单/展示时注意）：

| 契约字段 | 说明 |
|---|---|
| `specialty` | 实际来自 `t_expert.domain`（专业领域） |
| `avatar` | 来自 `t_user.avatar`，可能为 null，**要有默认头像兜底** |
| `rating` | 0.00~5.00，用 `el-rate` 展示（`disabled` + `allow-half`） |
| `answerCount` | 已回答问题数 |

#### 10. `/question/ask` —— 提问

| 操作 | 接口 |
|---|---|
| 提问 | `POST /api/question`，body `{ expertId?, title, content }` |
| 回答 | `PUT /api/question/{id}/answer`，body `{ answer }`（仅 expert） |

- `expertId` **可选**：填了 = 定向提问（只有该专家能答）；不填 = 公开提问（任何已审核专家都能答，先到先得）
- 不能向自己提问（**4006**）；专家不存在或未过审 → **4001**
- 已回答的问题不能再答 → **4003**
- 回答成功会让该专家的 `answerCount` +1（所以专家列表的"已回答"数字是活的）

#### 11. `/question/my` —— 我的提问（**⚠️ 和专家的待办是同一个接口**）

| 项 | 内容 |
|---|---|
| 接口 | `GET /api/question/list?status=` |
| 返回 | `List<QuestionVO>`（**不是分页**） |

**这个接口按登录角色返回不同数据，务必理解**：

| 登录角色 | 返回什么 |
|---|---|
| `farmer` / 其他人 | **我发起的提问** |
| `expert` | **别人点名问我的 + 面向所有专家的公开提问 + 我自己提的** |

也就是说，**专家的"待回答"待办列表用的就是这个接口**（契约里没有单独的"专家待办"接口）。
专家登录后进这个页面，看到的就是该他处理的请求 —— 这是设计意图，不是 bug。

同样地，**预约列表也是这样**：

| 接口 | farmer 视角 | expert 视角 |
|---|---|---|
| `GET /api/appointment/list` | 我发起的预约 | 约给我的 + 我发起的 |

**预约页（`/appointment`，你的清单里没列但接口已就绪）**：

| 操作 | 接口 | 注意 |
|---|---|---|
| 发起 | `POST /api/appointment` | `type=online` **必填 `meetingLink`**；`type=offline` **必填 `meetingPlace`**（后端校验） |
| 列表 | `GET /api/appointment/list` | 见上表 |
| 处理 | `PUT /api/appointment/{id}/handle` | 仅被预约的专家；body `{ "status": "ACCEPTED" }` 或 `"REJECTED"` |

- `appointmentTime` 必须**晚于当前时间**，否则 **4004**
- 已处理的预约不能重复处理，否则 **4005**
- 预约状态是**字符串**：`PENDING` / `ACCEPTED` / `REJECTED`；后端额外返回 `statusName`（待处理/已接受/已拒绝）和 `typeName`（线上/线下），**直接用中文名字段，别在前端再写一份映射**

`request.js` 已经处理了通用错误码，**业务错误码（3xxx/4xxx）你直接在 catch 里读 `message` 弹提示即可**。

## 六、建议的实现顺序

1. **先跑通一条链路**：`/financing/apply` → 提交 → 弹匹配小组 → 跳 `/financing/groups` 加入。
   这条链路把「带 Token 请求 → 拆封 data → 分页 → 错误提示」全走了一遍，
   跑通后其余页面都是重复劳动。**别一上来就摊开做 11 个页面。**
2. 再做 `/financing/my`（列表 + 详情 + 取消）和 `/financing/group/:id`。
3. 银行 3 页（数据量小、逻辑直白，适合快速拿分）。
4. 专家 4 页（列表/详情是纯展示，提问/回答涉及两个角色视角，放最后）。
5. 最后统一处理加载态（`v-loading`）、空状态（`EmptyState`）、表单校验。

**如果时间不够可以砍的**（后端接口仍然存在，只是前端不做入口）：

- 文章评论的 UI（接口已就绪）

- `/bank/stats` 的图表（用纯数字卡片）
- 富文本编辑器（`textarea` 就够了，发布接口收的是纯文本）
