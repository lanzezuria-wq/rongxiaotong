## 一、开工前必须先定的三件事

### 1. 架构：继续用单模块，不拆多模块

**结论：跟 P1 现状走，继续在 `demo1` 里加代码。**

任务包 `07-项目目录结构` 要求 Maven 多模块（`rxt-common` / `rxt-system` / `rxt-trade` / `rxt-app`），
但 P1 实际交付的是单模块 `demo1`。现在拆模块的代价：

| 方案 | 代价 | 风险 |
|---|---|---|
| 拆成多模块 | 要重构 P1 的 62 个源文件 + 全部 import + 启动类 | 高。P1 已推送，重构产生的巨量 diff 会覆盖别人的改动 |
| 继续单模块 | 只需 1 行 `@MapperScan` 改动 | 低 |

**P2 用 `com.rxt.trade.*` 子包隔离自己的代码**，保留模块边界，将来真要拆模块时整包搬走即可。

```
com.rxt                      ← P1（已有）
├── common / config / security / entity / mapper / service / controller / dto / vo
└── trade                    ← P2 新增
    ├── entity      Product / ProductDemand / Cart / Order / OrderItem / Address
    ├── mapper      对应 6 个 Mapper
    ├── dto         入参
    ├── vo          出参
    ├── constant    ProductConst / OrderConst
    ├── service     + service/impl
    └── controller  ProductController / CartController / OrderController
                    AddressController / HomeController
```

### 2. 字典表名：用 `t_dict`，不是 `t_dictionary`

任务包 `06` 建的是 `t_dictionary`，**但 P1 实际建的是 `t_dict`**（`init.sql` + `DictItem` 实体 + `DictItemMapper` 全都是 `t_dict`）。

P2 的商品表用 `category_code` 关联字典值，**必须跟随 P1 的 `t_dict`**。
任务清单 `03` 里那句注释「关联 t_dictionary.type=product_category」是错的，照抄会查不到表。

### 3. ⚠️ 补一张 `t_cart` 表 —— 任务包漏了

**任务包 17 张表里没有 `t_cart`**，但：
- `03` 任务清单要求 4 个购物车接口
- `08` 契约里定义了 `GET /cart/list`、`POST /cart`、`PUT /cart/{id}`、`DELETE /cart/{id}`

**接口有，表没有。** P2 必须自己补建。字段从契约反推：

```sql
CREATE TABLE t_cart (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  product_id BIGINT NOT NULL,
  sku_spec VARCHAR(100) COMMENT '规格，无 SKU 商品为空',
  quantity INT NOT NULL DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_product_sku (user_id, product_id, sku_spec),
  INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='购物车';
```

> `CartVO` 里的 `productName` / `productImage` / `price` / `stock` **不入库**，
> 是查询时 join `t_product` 实时取的 —— 否则商品改价后购物车显示的是旧价。
> `UNIQUE KEY` 保证同一商品同一规格不重复加购，加购时走 `ON DUPLICATE KEY` 或先查后加。

### Step 1 · 地基对齐（改 P1 的 3 处，共 3 行）
| 动作 | 文件 | 改什么 |
|---|---|---|
| 1.1 | `RxtApplication.java` | `@MapperScan("com.rxt.mapper")` → `@MapperScan("com.rxt.**.mapper")`，否则 P2 的 Mapper 扫不到 |
| 1.2 | `ResultCode.java` | 补 2002；按需补订单相关码（3002 已被 P3 占，别碰） |
| 1.3 | `SecurityConfig.java` | 加 P2 路径规则（见下） |

**SecurityConfig 要加的规则**（插在 `anyRequest().authenticated()` 之前）：

```java
// 首页 + 商品浏览：游客可见（SRS 表标注认证为 ×）
.requestMatchers(HttpMethod.GET, "/api/home/**").permitAll()
.requestMatchers(HttpMethod.GET, "/api/product/list", "/api/product/*").permitAll()
// 商品发布/编辑/上下架/删除：仅农户本人（Service 层再校验归属）
.requestMatchers(HttpMethod.POST, "/api/product").hasRole("farmer")
.requestMatchers(HttpMethod.PUT, "/api/product/**").hasRole("farmer")
.requestMatchers(HttpMethod.DELETE, "/api/product/**").hasRole("farmer")
// 购物车 / 订单 / 地址：登录即可，归属由 Service 校验
// （无需显式配，走 anyRequest().authenticated()）
```

> ⚠️ `.requestMatchers(HttpMethod.GET, "/api/product/*")` 用的是**单星号**，
> 只匹配 `/api/product/123`，不会匹配 `/api/product/list` —— 两者都要单独写。

### Step 2 · 建表
产出 `demo1/src/main/resources/sql/init_trade.sql`，包含 6 张 P2 表 + 种子数据。
**独立成文件**，不改 P1 的 `init.sql`，避免 git 冲突。

### Step 3 · 实体 + Mapper（6 组）
`Product` / `ProductDemand` / `Cart` / `Order` / `OrderItem` / `Address`
+ 6 个 `extends BaseMapper<T>`。
要点：`@TableName` 显式声明表名，`@TableId(type = IdType.AUTO)`。

### Step 4 · DTO / VO
DTO 是入参契约（带 `@NotBlank` / `@Min` 校验），VO 是出参契约。

每个业务一个接口 + 一个实现。**金额一律 `BigDecimal`，禁用 `double`**。

### Step 6 · Controller（5 个）

## 五、订单状态机（P2 最难的部分，单独讲）

```
0 待付款 ──支付──→ 1 待发货 ──发货──→ 2 已发货 ──收货──→ 3 已完成
   │
   └──取消／15分钟超时──→ 4 已取消
```

**必须守住的规则：**

1. **状态只能按箭头走**，不能跳级、不能回退。每次变更前校验当前状态。
2. **扣库存必须加行锁**：`SELECT ... FOR UPDATE`，否则并发下单会超卖。
3. **创建订单是一个事务**：扣库存 + 写 `t_order` + 写 `t_order_item`，任一失败全部回滚。
4. **取消订单要还库存**（`stock += quantity`）。
5. **15 分钟超时**：演示版可简化为「查列表时顺手把 `expire_at < now() && status=0` 的置为已取消」，
   不必上定时任务或 Redis。
6. **订单号**：`RXT + yyyyMMddHHmmss + 6 位随机`，字段有 `UNIQUE` 约束，重复会插入失败。
7. **越权校验**：发货只能由 `farmer_id` 本人、收货只能由 `buyer_id` 本人、取消同买家。
   **只靠 `hasRole` 不够**，必须在 Service 里比对当前用户和订单上的 id。
